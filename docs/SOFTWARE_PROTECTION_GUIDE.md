# 软件加密和保护建议

## 目标

这个文档用于说明 FriendAuto 项目里哪些内容需要重点保护，哪些内容不建议加密，以及客户端、自动化脚本、服务器和数据库应该怎么处理。

软件加密不是为了让别人完全看不到任何东西，而是为了提高破解、复制、篡改的成本。真正关键的会员、次数、订单、账号状态，必须放在服务器判断。

## 最需要保护的内容

### 1. 后端环境配置

重点文件：

```text
server/.env
```

这个文件里通常包含：

```text
DATABASE_URL
SECRET_KEY
SMTP_HOST
SMTP_PORT
SMTP_USER
SMTP_PASSWORD
支付相关密钥
```

处理方式：

- 不要上传到 Git。
- 不要打包进客户端。
- 只放在服务器上。
- 服务器权限要限制，普通用户不能随便读取。
- 如果泄露，需要立即更换数据库密码、邮箱授权码、`SECRET_KEY`。

## 客户端需要保护的内容

重点目录：

```text
desktop/src
desktop/dist
desktop/src-tauri
```

客户端源码不会直接发给用户，但打包后的前端 JS、CSS、EXE 仍然可能被反编译或查看。

建议处理方式：

- 发布给用户时，只发打包后的安装包或 EXE。
- 前端构建时可以开启压缩和混淆。
- Tauri/Rust 端可以使用 release 构建。
- 不要在客户端写死数据库密码、管理员密码、支付密钥。
- 客户端只负责展示状态，最终会员状态和免费次数必须向服务器查询。

## 自动化脚本需要重点保护

重点文件和目录：

```text
scripts/platform_worker.py
automation/autodoor_behavior_tree
automation/Addfriend/tree.json
automation/Addfriend/images/templates
```

这些内容包含：

- 微信自动化执行流程。
- 加好友行为树。
- 图片识别模板。
- 点击、输入、判断逻辑。

建议处理方式：

- 不直接把 `.py` 源码发给用户。
- 可以使用 PyInstaller 打包成 EXE。
- 可以使用 PyArmor、Nuitka 等工具做混淆或编译。
- 行为树和模板如果必须放到客户端，建议至少做压缩、混淆或资源打包。
- 关键业务判断不要只写在这些脚本里，仍然要由服务器确认权限。

## 会员和免费次数逻辑

这部分不要只靠客户端加密。

正确做法：

- 客户端开始任务前，请求服务器确认会员状态和免费次数。
- 用户每加一条数据，不管成功、失败、无效，都由服务器记录并扣次数。
- 会员过期、免费次数用完，由服务器返回状态。
- 客户端只根据服务器返回结果弹充值窗口。

原因：

客户端代码一定可能被用户拿到或修改。如果会员判断只在客户端，别人可以绕过限制。

## 不建议加密或加密意义不大的内容

### API 地址

例如：

```text
http://47.111.3.83:8001
```

API 地址藏不住，因为客户端请求服务器时一定能被抓包看到。

正确做法不是隐藏 API 地址，而是：

- 所有接口都要鉴权。
- Token 要有过期时间。
- 后端要校验用户权限。
- 重要操作要在服务器记录日志。

### 普通 UI 资源

例如：

```text
desktop/public
desktop/src/assets
```

这些普通图标、样式、页面资源一般不用重点加密。除非资源里包含你的自动化识别关键模板。

## 数据库保护

当前 MySQL 默认端口：

```text
3306
```

建议：

- MySQL 版本使用 5.7 时，要确认服务器实际安装的是 MySQL 5.7。
- 不建议把 `3306` 端口直接开放给公网。
- 如果数据库和后端在同一台服务器，优先让后端通过 `127.0.0.1:3306` 连接。
- 如果数据库必须远程访问，只允许指定服务器 IP 访问。
- 数据库账号不要使用 root。
- 给项目单独创建数据库账号，例如 `useradmin`。
- 只给项目需要的数据库权限。

## 推荐保护方案

### 最低成本方案

适合当前阶段：

1. `server/.env` 不上传、不发给用户。
2. 数据库密码只放服务器。
3. 客户端只发布安装包。
4. 自动化脚本用 PyInstaller 打包。
5. 会员和次数全部由服务器判断。

### 更稳的方案

适合正式发布：

1. 后端只部署在服务器。
2. MySQL 不开放公网。
3. 客户端代码压缩混淆。
4. Python 自动化代码用 PyArmor 或 Nuitka 混淆/编译。
5. EXE 加签名，减少被杀毒软件误报。
6. 服务端增加接口频率限制和操作日志。
7. 关键请求加设备绑定和 Token 校验。

## 总结

最重要的原则：

- 密码、密钥、数据库连接信息只放服务器。
- 客户端可以被保护，但不能完全信任。
- 会员、免费次数、订单状态必须由服务器最终判断。
- 自动化脚本和行为树是客户端里最需要保护的部分。
- MySQL 端口是 `3306`，生产环境不要随便对公网开放。
